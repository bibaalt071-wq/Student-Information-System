# SIS — серверге қосылатын нұсқа

Бұл жоба бұрынғы SIS демосының дизайнын, университет пәндерін және GPA есебін негізге алып дайындалды. HTML ішіндегі демо парольдер, браузердегі жергілікті бағалар және тек браузер тексеретін Face ID кіруі қолданылмайды. Алдыңғы HTML файл жеке демо болып қалады; оның деректері автоматты түрде көшірілмейді.

**Күйі: іске қосуға дайындалған бастапқы код. Нақты Supabase жобасына қосылмаған, интернетке жарияланбаған. Нақты адамдарды тіркеуден бұрын төмендегі іске қосу тексеруін орындау қажет.**

## Жоба құрамында

- Email және құпиясөзбен тіркелу/кіру, email растау, парольді қалпына келтіру.
- Жаңа аккаунтқа `student/pending` мәртебесі беріледі. Рөл сұрау параметріне немесе браузерге сеніп тағайындалмайды.
- Әкімші рөл, белсенділік және топты бекітеді; пәнге оқытушы тағайындайды.
- Студент өз бағаларын көреді. Оқытушы өзінің пәніне тіркелген белсенді студенттерге баға қояды. Шектеулер PostgreSQL RLS арқылы орындалады.
- 53 пәннен тұратын бастапқы каталог; атауы, бағыты, кредиті, тобы, оқытушысы өзгертіледі. Нақты оқу жоспарына сай кредиттерді түзету керек: бастапқы мәні — 5.
- Пәнге тіркелу, кесте, тапсырмалар, жеке файлдар, хабарландырулар.
- Ағымдағы GPA: әр пәннің бағаларының жай орташа мәні → әріптік шкала → кредитпен өлшенген орташа. Ресми транскрипт есебі, семестрлер, емтихан/рейтинг коэффициенттері және қайта тапсыру ережелері енгізілмеген.
- Баға, профиль және пән өзгерістері аудит журналында сақталады. Қатар өзгертілген жазбаны байқамай басып жазбау үшін `version` тексеріледі.
- Passkey тіркеу, кіру, тізімдеу және жою интеграциясы. Әдепкіде өшірулі.

## 1. Supabase жобасын ашу

1. https://supabase.com/dashboard мекенжайында өз аккаунтыңызбен кіріңіз.
2. Жаңа жоба ашыңыз. Дерекқор паролін өзіңіз сақтаңыз, чатқа немесе кодқа жазбаңыз.
3. Нақты студент деректері үшін өңірді, сақтау мерзімін және резервтік көшіру тәртібін оқу орныңыздың жауапты тұлғасымен анықтаңыз.
4. Жаңа жобаның SQL Editor бөлімінде `supabase/001_schema.sql`, одан кейін `supabase/002_courses.sql` файлдарын орындаңыз. Біріншісі тек жаңа жобаға арналған; қайта орындау үшін кестелерді өшірмеңіз.
5. Authentication баптауында email/password кіруін және **Confirm email** функциясын қосыңыз. Жаңа пароль ұзындығын сервер жағында кемінде 12 таңба етіп қойыңыз.
6. Нақты қолданушыларға растау және парольді қалпына келтіру хаттарын жіберу үшін **Custom SMTP** баптаңыз. Supabase-тің стандартты тест поштасы жалпы пайдалануға жеткіліксіз; ол жоба тобының рұқсат етілген адрестеріне шектеледі. SMTP парольдері тек Supabase панелінде сақталады.
7. Project URL және **Publishable key** мәндерін табыңыз. Бұл екеуі клиент конфигурациясына арналған. `service_role`, `sb_secret_...`, дерекқор паролі немесе жеке access token фронтендке салынбайды.

## 2. Жергілікті іске қосу

Node.js 22.12+ қажет.

```sh
npm ci
cp .env.example .env.local
```

`.env.local` ішіне өз жобаңыздың мәндерін енгізіңіз:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
VITE_ENABLE_PASSKEYS=false
```

```sh
npm test
npm run dev
```

Терминал көрсеткен localhost URL-ін ашыңыз. HTML файлды екі рет шертіп ашу жеткіліксіз. Қосылу мәндері жоқ кезде «Жүйе бапталуда» экраны шығады, жалған кіру берілмейді.

## 3. GitHub Pages немесе Vercel хостингі

**GitHub Pages:** GitHub-та жаңа repository ашып, осы жобаның файлдарын соған жіберіңіз. Repository → Settings → Pages → Build and deployment → Source: **GitHub Actions**. Repository → Settings → Secrets and variables → Actions → Variables ішіне `VITE_SUPABASE_URL` және `VITE_SUPABASE_PUBLISHABLE_KEY` мәндерін, қажет болса `VITE_ENABLE_PASSKEYS=false` қосыңыз. Тек publishable key қолданылады; secret/service_role ешқашан репозиторийге салынбайды. `main` тармағына жіберілгенде `.github/workflows/pages.yml` тесттерді жүргізіп, сайтты жариялайды. Айнымалылар қойылмаса workflow жариялаудан бұрын тоқтайды. Сайт адресі `https://атыңыз.github.io/репозиторий/` түрінде болуы мүмкін. Supabase-те Site URL және Redirect URLs ретінде өзіңізге шыққан **нақты** GitHub Pages HTTPS мекенжайын толық жолымен (`/репозиторий/`) қосыңыз. Passkey баптауындағы RP ID үшін `атыңыз.github.io`, origin үшін `https://атыңыз.github.io` қолданыңыз; жол RP ID не origin ішіне кірмейді. Жеке доменге кейін көшсеңіз, бұрын тіркелген passkey қайта бапталады. GitHub Pages тек сыртқы беттерді жариялайды, база, пароль, рөл және файлдарды сақтау үшін Supabase жобасы бәрібір қажет. GitHub аккаунтыңыз бар болса, Supabase Dashboard-қа **Continue with GitHub** арқылы тіркеліп көріңіз.

**Vercel баламасы:**

1. Кодты өзіңіздің **жеке GitHub репозиторийіңізге** орналастырыңыз. `node_modules`, `.env.local` және құпия кілттерді қоспаңыз.
2. Vercel-де осы репозиторийден жоба импорттаңыз. Framework: **Vite**, build: `npm run build`, output: `dist`.
3. Environment Variables бөліміне жоғарыдағы үш мәнді қойыңыз. Node.js 22.12+ таңдаңыз.
4. Deploy аяқталған соң тұрақты HTTPS мекенжайын алыңыз. Қажет болса өз доменіңізді кейін қосасыз. Бұл пакетте домен сатып алынбаған және ақылы жоспар қосылмаған.
5. Supabase Authentication → URL Configuration: **Site URL** ретінде сол HTTPS мекенжайын орнатыңыз; **Redirect URLs** тізіміне оның `/` мекенжайын дәл қосыңыз. Өндірістік жобаға барлық preview домендерін wildcard арқылы қоспаңыз.
6. Vercel конфигурациясында `.supabase.co` қосылымдарына арналған CSP бар. Supabase-ке жеке домен қолдансаңыз, `vercel.json` ішіндегі `connect-src` мәнін нақты API origin-ге сәйкестендіріңіз.

Сайтты жай ғана жариялау дерекқор мен email қызметін автоматты баптамайды. Оларды жоғарыдағы ретпен бөлек байланыстыру керек.

## 4. Бірінші әкімші

1. Сайтыңыздан өз email-іңізбен тіркеліп, email-ді растаңыз.
2. Supabase SQL Editor-де `003_first_admin.sql` файлын ашыңыз. Ішіндегі placeholder-ді өзіңіздің расталған email-іңізге ауыстырып орындаңыз.
3. Сайтта «Күйін тексеру» басыңыз. «Пайдаланушылар» бөлімінен қалған аккаунттарды тексеріп бекітіңіз.
4. Оқытушыны `teacher/active`, студентті `student/active` етіп орнатып, топтарын белгілеңіз.
5. «Пәндер» бөлімінен оқытушыны пәнге тағайындаңыз. Белгілі топ үшін `group_name` мәнін студент тобымен дәл сәйкестендіріңіз.
6. Студент пәнге тіркелгеннен кейін оқытушы оны баға қою тізімінен көреді. Пәннің тобы бос болса, кез келген белсенді студент тіркеле алады.

Бірінші әкімші автоматты түрде «бірінші тіркелушіге» берілмейді. Бекітуді тек жоба иесі SQL Editor-де орындайды. Өзіңіздің әкімші рөліңізді осы интерфейс арқылы түсіруге болмайды.

## 5. Face ID / Touch ID / passkey

Supabase құжаттамасында бұл мүмкіндік **experimental** деп белгіленген. Код `@supabase/supabase-js 2.105.0` нұсқасына бекітілген. Нақты құрылғыдағы тексеруден бұрын email/құпиясөз негізгі кіру тәсілі болып қалады.

1. Алдымен сайттың тұрақты доменін таңдаңыз.
2. Supabase Authentication → Passkeys бөлімінде мүмкіндікті қосыңыз.
3. RP Display Name: `SIS`; RP ID: протоколсыз нақты домен; RP Origins: нақты HTTPS origin.
4. `VITE_ENABLE_PASSKEYS=true` орнатып қайта deploy жасаңыз.
5. Расталған аккаунтпен кіріп, «Профиль және кіру» → «Passkey қосу» басыңыз.
6. Шығып, passkey арқылы қайта кіріп көріңіз. Құрылғы Face ID, Touch ID, PIN-код немесе басқа authenticator ұсынуы мүмкін; сайт бет суретін жинамайды.

RP ID өзгерсе, бұрын тіркелген кілттер жарамсыз болады. Сондықтан тұрақты доменді алдын ала таңдаңыз. Passkey құру мен тексерудің challenge және қолтаңба қадамдарын Supabase Auth орындайды, браузерде өз бетімен сессия жасалмайды.

## 6. Файлдар және сессиялар

- `sis-files` bucket-і жеке. Файлдарға оқу/жазу RLS ережелері қолданылады, public URL берілмейді.
- Бір файлдың шегі — 10 МБ. PDF, TXT, PNG, JPG, ZIP, DOCX, PPTX, XLSX қабылданады.
- Жұмысты қайта жібергенде жаңа объект жасалады, бұрынғы файл үстінен жазылмайды. Жүктеу сәтті болып, жазба сақтау сәтсіз болса, тіркелмеген объект қалуы мүмкін. Осындай және ескі объектілерді тазалау үшін кейін серверлік retention/cleanup жұмысы қажет; клиентке объектілерді жаппай жою құқығы берілмеген.
- Сервер файл мазмұнын антивируспен тексермейді; оқу орнында қажет болса scanning қызметін қосу керек.
- Сессия токені осы қойындының `sessionStorage` қоймасында сақталады; бағалар мен парольдер localStorage-қа жазылмайды. Email сілтемесі жаңа қойындыда ашыла алуы үшін тек уақытша PKCE verifier localStorage-та сақталады. Сілтемені сұраған браузерде ашыңыз.
- «Шығу» осы сессияны аяқтайды; пароль қалпына келтірілген соң барлық сессияларға sign-out сұрауы жіберіледі. Бұғатталған аккаунттың оқу деректеріне қолжетімділігін дерекқор әр сұрауда тексереді.

## Тексеру нәтижесі және шегі

`npm test`: GPA, нақты PostgreSQL қозғалтқышындағы (PGlite) RLS ережелері және DOM интерфейс тесттері. SQL тесттері Supabase auth/storage схемаларының шағын көшірмесін қолданады. DOM тесттері Auth API-ін имитациялайды; олар нақты email жеткізілуін немесе биометриялық құрылғыны тексермейді.

`npm run build`: статикалық production жинағы жасалады. Браузерде конфигурациясы жоқ күйдің дұрыс жабық қалатыны тексерілді. Нақты Supabase/PostgREST/Storage және Face ID арқылы толық кіру сынағы әлі жасалған жоқ: жоба байланысы жоқ.

Нақты студенттерді қоспас бұрын кемінде 2 студент, 2 оқытушы және 1 әкімші тест аккаунтымен тіркелу, email растау, парольді қалпына келтіру, өзге студенттің бағасына тыйым, өзге оқытушының пәніне тыйым, жеке файлдар, телефондағы көрініс және сессиядан шығу сценарийлерін нақты серверде тексеріңіз. Резервтік көшірмені қалпына келтіруді де сынаңыз.

Бұл нұсқа шағын пилотқа арналған бастапқы жоба: барлық рұқсат етілген жазбалар жүктеледі, үлкен көлем үшін экран бойынша pagination және серверлік есептер керек. Топтар мәтінмен белгіленеді; бірнеше семестр/ағым үшін бөлек course offering моделі әлі жоқ. Демоның өңдеу сценарийлері түгел көшірілмеген: оқу тапсырмасын жою/өңдеу, bulk enrollment және аккаунтты толық жою интерфейсі қосылмаған. Нақты пайдалану алдында оқу орнының процестерімен сәйкестендіріледі.
